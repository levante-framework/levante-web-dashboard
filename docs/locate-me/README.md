## Locate Me (Interactive) + Locate Me Gallery (Static) — Engineering Notes

This repo contains **two related experiences**:

- **Interactive “Locate Me” page**: `public/locate-me.html` + `public/js/locate-me-v2.js`
- **Static “Locate Me Gallery”**: `public/gallery/locate-me/` generated by scripts under `scripts/`

This document is intended to be sufficiently detailed for another model/engineer to continue work without re-discovering context.

---

## 1) High-level behavior

### 1.1 Interactive Locate Me (runtime)

- The user clicks **Locate Me**, grants browser geolocation permissions, and the app:
  - Finds nearby cities **on-device** using a compact city dataset.
  - Finds **admin boundaries locally** using prebuilt, gzipped **ADM packs** (no per-request OSM/Overpass fetch).
  - Renders an interactive Leaflet map (OSM tiles) with:
    - GPS point
    - 2 & 10-mile circles
    - Regional boundary (blue)
    - Local boundary (red)
    - A small in-map **legend**, including **coarse weather**.

**Primary files**
- UI: `public/locate-me.html`
- Logic: `public/js/locate-me-v2.js`

### 1.2 Locate Me Gallery (build-time)

- We maintain a curated set of seed points in `public/gallery/locate-me/seed-points.json`.
- Running `scripts/generate-locate-me-gallery.js` simulates the same workflow (nearest-city + polygons) and writes:
  - `public/gallery/locate-me/gallery-data.json`
- Running `scripts/generate-gallery-images.js` generates static images for each gallery item using:
  - **Mapbox Static Images API** for basemap tiles
  - A small GeoJSON overlay (point + circles + simplified polygon outlines)
  - **Sharp** compositing for an SVG legend + scale bar overlay
  - **Open‑Meteo** weather snapshot
  - Population estimates (see below)

**Primary files**
- Seed points: `public/gallery/locate-me/seed-points.json`
- Data generation: `scripts/generate-locate-me-gallery.js`
- Image generation: `scripts/generate-gallery-images.js`
- Output data: `public/gallery/locate-me/gallery-data.json`
- Output images: `public/gallery/locate-me/images/*.webp`

## 2) Data sources & on-disk assets

### 2.1 Offline city dataset (GeoNames)

- Source: GeoNames `cities5000` dump.
- Build script: `scripts/geocoder/build-geocoder.js`
- Output: `data/geocoder/cities.min.json` (and typically gzipped to `data/geocoder/cities.min.json.gz`)
- Record schema:
  - `{ id, name, ascii, lat, lon, country, admin1, admin2, population }`

Used by:
- Interactive locate-me for nearest-city lookup
- Gallery generator for nearest-city lookup
- Gallery image generator for population estimation (summing cities-in-polygon)

### 2.2 ADM packs (GeoBoundaries → gzipped FeatureCollections)

We use GeoBoundaries gbOpen boundaries to build **gzipped client packs**:

- `public/adm0/countries.min.json.gz` (ADM0)
  - Build script: `scripts/adm/build-adm0.js`
- `public/adm-packs/<iso2>/adm{1,2,3,4}.json.gz`
  - Build script: `scripts/adm/build-packs.js`

These packs are used for local point-in-polygon lookup on-device or in scripts.

### 2.3 US-specific “local” boundaries

The US needs an “in-between” boundary between **tracts** (very small) and **counties** (very large).

We added **US place/city boundaries** (Census TIGER/Line “PLACE”), stored per-state:

- `public/adm-packs/us/adm3-place/<state>.json.gz`
- Build script: `scripts/us/build-us-place-boundaries.js`
- NPM helper: `npm run adm:build:us-place` (see `package.json`)

We still keep tract-level packs for fallback:

- `public/adm-packs/us/adm3/<state>.json.gz`
- Build script: `scripts/us/build-us-tract-adm3.js`

### 2.4 Gallery weather cache (local-only)

Gallery image generation caches Open‑Meteo responses to avoid hammering the API:

- Cache file: `data/gallery/weather-cache.json`
- Ignored by git via `.gitignore`.

## 3) Boundary selection rules (red vs blue)

### 3.1 Runtime (interactive)

In `public/js/locate-me-v2.js`:

- **Blue**: ADM2 pack lookup (regional)
- **Red**:
  - For `US`: prefer **adm3-place** (place/city) → fallback to tract adm3 → fallback to ADM2
  - For other countries: prefer ADM3 pack → fallback to ADM2

The red layer is drawn **after** blue to avoid being hidden when boundaries overlap.

### 3.2 Gallery

In `scripts/generate-locate-me-gallery.js` and `scripts/generate-gallery-images.js`:

- Gallery data (`gallery-data.json`) stores “regional” (ADM2) and “local” (ADM3/ADM4) polygons.
- Gallery image generation further improves US local outlines by loading `adm3-place` where possible.

## 4) Legend contents (gallery images)

The gallery legend is an SVG composited onto the Mapbox image:

- GPS point
- “2 & 10-mile circles”
- Red local boundary label + population estimate
- Blue regional boundary label + population estimate
- “Polygons downloaded” (estimated pack bytes; tries to reflect real runtime behavior)
- **Weather** snapshot + observed timestamp

### 4.1 Population estimation (gallery)

GeoBoundaries polygons do not include population. We estimate population by:

- Taking the polygon (red/blue)
- Summing `cities.min.json.gz` city populations whose points fall inside the polygon
- (bbox prefilter → point-in-polygon)

This is approximate and depends on GeoNames city coverage.

## 5) Weather strategy

### 5.1 Interactive page (privacy-preserving)

`public/js/locate-me-v2.js` fetches weather from Open‑Meteo using a **coarse query point**:

- Prefer ADM2 bbox center
- Else nearest-city center
- Else GPS rounded to 1°

Then it rounds the query point further (0.25°) before the network call and caches in `localStorage` (~45 minutes).

### 5.2 Gallery images (direct)

Gallery images use the known seed lat/lon and call Open‑Meteo directly (with coarse rounding for caching).

## 5b) Air quality strategy (AQICN / WAQI, privacy-masked)

### 5b.1 Interactive page

`public/js/locate-me-v2.js` adds a privacy-masked air quality lookup:

1. **Faux location** — the raw GPS is shifted by `AQI_SHIFT_KM` (1 km) in a direction
   that is deterministic per coarse-region + day (`shiftLocationForPrivacy`). This
   mirrors the geo-strategy gallery faux-location approach so the requested area's
   center is not the device's true position.
2. **Area request** — a `AQI_BBOX_KM` (10 km × 10 km) bounding box is built around the
   faux center (`boundingBoxAround`) and sent to `/api/air-quality?latlng=...`. Only the
   de-identified box leaves the device; the raw GPS never does.
3. **On-device selection** — the proxy returns every reporting station inside the box; the
   device picks the station **closest to the raw GPS** (`approxDistanceKm`). The raw GPS is
   used only locally for this ranking.
4. **Enrichment** — the chosen station is enriched via its **public station id**
   (`/api/air-quality?uid=...`), which yields the dominant pollutant and per-pollutant
   values without involving any coordinates.
5. **Storage** — the stored measurement (`entry.airQuality`) includes AQI, EPA category,
   dominant pollutant, station name, distance, and the privacy basis. Station coordinates
   and raw GPS are intentionally omitted. Results are cached in `localStorage` (~30 min).

### 5b.2 Server proxy and token

- Endpoint: `api/air-quality.js` (proxies WAQI `v2/map/bounds` and `feed/@<uid>`).
- The secret token is read from **`WAQI_TOKEN`** (or `AQICN_TOKEN`) and is never exposed to
  the client. Get a free token at https://aqicn.org/data-platform/token/.
- The proxy rejects bounding boxes larger than ~0.35° per side so it cannot be used as a
  wide-area scraper, and it never logs or stores coordinates.

## 6) Seed points & filtering

Seed points live in `public/gallery/locate-me/seed-points.json`.

- Each point:
  - `{ id, label, country, lat, lon }`
  - Optional: `allowFar: true`

`allowFar: true` is used for remote points (e.g., Terlingua) where the nearest city in the GeoNames dataset may be >20km away.

Implementation:
- `scripts/generate-locate-me-gallery.js` default filter is `MAX_DISTANCE_KM = 20`, unless `allowFar` is set.

## 7) How to run (common workflows)

### 7.1 Build/update ADM packs

```bash
# ADM0 countries
node scripts/adm/build-adm0.js

# ADM1-ADM4 per country
node scripts/adm/build-packs.js --countries=US,DE,GB,NL,CA,CO,IN,AR,GH,CH

# US tract packs (fallback local)
node scripts/us/build-us-tract-adm3.js --states=CA,OR,FL,NY,IL --year=2024 --precision=3 --maxPoints=250

# US place packs (preferred local in US)
npm run adm:build:us-place
```

### 7.2 Regenerate gallery data + images

```bash
node scripts/generate-locate-me-gallery.js
node scripts/generate-gallery-images.js
```

Selective image regeneration:

```bash
node scripts/generate-gallery-images.js --only=US-chicago
```

### 7.3 Deploy

```bash
npm run deploy
```

Deploy notes:
- `scripts/deploy-and-alias.js` runs `scripts/apply-version.js` then deploys to Vercel and aliases:
  - `levante-cockpit.vercel.app` (and others)
- Vercel function size limits are handled via:
  - `.vercelignore`
  - `vercel.json` `excludeFiles` for APIs that don’t need large `data/*` caches.

## 8) Known gotchas / operational notes

### 8.1 Mapbox Static Images token

Gallery image generation requires `MAPBOX_ACCESS_TOKEN` with access to Static Images.
If you see `401 Direct access not allowed`, check token scopes/restrictions.

### 8.2 Vercel “Serverless Function exceeded 250MB”

If deployment fails with this, it’s usually because large `data/*` directories got bundled into a serverless function.
Current mitigations:
- `.vercelignore` ignores heavy caches (e.g., `data/tiger/`)
- `vercel.json` sets `excludeFiles` for `api/location-log.js`, `api/list-validation-files.js`, `api/get-validation-file.js`

### 8.3 Tags / milestones

- A baseline tag exists: `adm2+3` (marks the “two-level boundaries” baseline before adding more enhancements).
