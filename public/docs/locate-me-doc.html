📍 Locate Me · Documentation

Documentation for the reverse geocoding and polygon lookup flow that powers the map on the Locate Me page.

Overview

The Locate Me feature uses GPS coordinates to find the nearest cities and display their boundaries on an interactive map. The system consists of two main APIs:

  • Reverse Geocoding API (/api/reverse-geocode) – Finds the nearest cities based on GPS coordinates
  • Polygon API (/api/gadm-polygon) – Retrieves administrative boundary polygons for display on the map

Reverse Geocoding

Data Source

The reverse geocoding API uses data/geocoder/cities.min.json.gz, a compressed dataset containing city locations worldwide. The dataset includes:

  • City names (original and ASCII)
  • Latitude/longitude coordinates
  • Country and administrative region codes (admin1, admin2)
  • Population data

Algorithm

The API uses a brute-force search algorithm optimized with bounding-box pre-filtering:

  1. Bounding Box Filter: Pre-filters cities using a quick lat/lon bounding box check (1 degree ≈ 111km) to reduce the search space
  2. Distance Calculation: Computes Haversine distance for all cities within the bounding box
  3. Distance Filter: Filters out cities beyond the maxDistanceKm threshold (default: 50km)
  4. Sorting & Selection: Sorts by distance and prioritizes cities in the same administrative region (admin1) as the nearest result

This approach ensures accurate results by scanning all candidates within range, not just the first N matches.

API Parameters

GET /api/reverse-geocode?lat=37.424&lon=-122.166&limit=3&maxDistanceKm=50
  • lat – Latitude (required)
  • lon – Longitude (required)
  • limit – Number of results (1-10, default: 3)
  • maxDistanceKm – Maximum search radius in kilometers (default: 50)

Polygon Lookup

Data Source

The polygon API uses OpenStreetMap (OSM) via Overpass Turbo to retrieve administrative boundaries. This provides more granular boundaries (towns, neighborhoods) compared to GADM data.

  • Overpass API: Queries https://overpass-api.de/api/interpreter for administrative boundaries
  • Admin Levels: Searches for admin_level 6-10 (counties, cities, towns, neighborhoods)
  • Country Support: Currently supports 10 countries (US, CA, CO, IN, AR, NL, GH, CH, DE, GB)

Workflow

  1. Initial Query: Queries Overpass for administrative boundaries containing the GPS point
  2. Filtering: Filters out counties (admin_level=6) if city/town boundaries (admin_level ≥ 7) are available
  3. Selection: Chooses the most specific boundary (highest admin level, then smallest area)
  4. Nearby City Fallback: If only a county is found, queries for nearby cities within 10km. If a city is within 5km, uses it instead of the county
  5. Caching: Caches responses for 5 minutes to reduce API calls

Example: Stanford University

Stanford doesn't have its own administrative boundary in OSM. The system:

  1. Finds Santa Clara County (admin_level=6) containing the point
  2. Queries for nearby cities within 10km
  3. Finds Menlo Park (admin_level=8) at 2.84km distance
  4. Returns Menlo Park's boundary instead of the huge county boundary

API Parameters

GET /api/gadm-polygon?country=USA&lat=37.424&lon=-122.166
  • country – Country code (required, must be in supported list)
  • lat – Latitude (required)
  • lon – Longitude (required)

Frontend Integration

The frontend (public/locate-me.html and public/js/locate-me-v2.js) handles:

  • GPS location detection via browser Geolocation API
  • Calling both APIs with the detected coordinates
  • Rendering polygons on a Leaflet map
  • Caching API responses to avoid redundant requests
  • Displaying city names and distances

The Documentation button in the header links to this page for easy reference.

Deployment

Before deployment, scripts/apply-version.js automatically:

  • Updates version numbers in HTML files
  • Adds cache-busting query strings to asset URLs
  • Ensures browsers load the latest code

Deployment is handled via scripts/deploy-and-alias.js, which:

  • Runs version updates
  • Deploys to Vercel
  • Sets up domain aliases
  • Verifies deployment across all aliases

Technical Details

Dependencies

  • @turf/boolean-point-in-polygon – Point-in-polygon testing
  • @turf/area – Polygon area calculation
  • @turf/distance – Distance calculations
  • @turf/centroid – Polygon centroid calculation
  • osmtogeojson – Converts OSM data to GeoJSON
  • zlib – Decompresses gzipped city data

Performance

  • Reverse geocoding scans all cities in the bounding box (typically 100-1000 cities)
  • Polygon queries are cached for 5 minutes to reduce Overpass API calls
  • City data is loaded once per serverless function invocation

Future Improvements

  • Add support for more countries
  • Consider using a spatial index (kdbush) for faster reverse geocoding if performance becomes an issue
  • Add support for custom boundary data sources
  • Implement offline polygon caching for frequently accessed regions
